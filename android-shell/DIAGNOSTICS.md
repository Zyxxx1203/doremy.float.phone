# Android 壳运行诊断与闪退恢复

## 用户遇到「一点开就闪退」时

1. **先不要清除应用数据、卸载或重装。** 这些操作可能删除本地聊天、角色记忆或未同步数据。
2. 使用包含启动恢复机制的新版 APK 启动一次。如果上次启动未能完成网页主页面加载，应用会进入原生「启动恢复」界面，不启动 WebView 和网页桥接，避免反复进入同一条崩溃路径。
3. 在恢复界面点击「复制诊断摘要」，把摘要发给维护者前先检查是否含有个人信息。
4. 确认后点击「退出恢复模式并重试（不清除数据）」。
5. 如果恢复界面也无法出现，或整个 Android 进程仍立即退出，需要系统级崩溃日志（见下文）。应用内诊断不能捕获发生在 Application/Activity 初始化前的所有崩溃、系统强杀或 ANR。

## 诊断功能覆盖范围

- 原生未捕获异常：尽力保存最近一次堆栈到应用私有目录 `last-native-crash.txt`；下一次启动进入恢复模式时可复制摘要。
- WebView 渲染进程退出：显示原生恢复界面，而不是只留下白屏。
- 网页主文档网络错误或 HTTP 错误：显示原生恢复界面，提供重试、外部浏览器和复制诊断摘要。
- 网页已打开时：设置 → 运行诊断，可检查站点连通性、存储接口、Android 版本/设备/WebView、通知/悬浮窗/使用情况访问/无障碍状态，并导出前端错误日志。
- 诊断不自动上传，不读取聊天记录、角色记忆或截图。分享前仍应人工检查。
- 本地诊断无法代替 Android 系统日志，也不能证明所有设备兼容。

## 如何取得系统级日志（恢复界面也无法打开时）

优先使用 Android Studio 的 Logcat，选择对应设备和应用进程，复现问题后搜索：

- `FATAL EXCEPTION`
- `AndroidRuntime`
- `Fatal signal`
- `chromium` / `WebView`
- `ANR in`

如果熟悉 ADB，可在电脑连接手机并开启 USB 调试后执行：

```bash
adb logcat -c
adb shell monkey -p app.floatphone.shell 1
adb logcat -d -v threadtime > float-phone-crash-log.txt
```

如果用户自行改过 applicationId / 包名，需要把命令中的 `app.floatphone.shell` 换成实际包名。不要把完整日志公开贴到公共 issue；它可能包含设备信息或其他应用日志，先筛选崩溃时间附近的片段并脱敏。

## 排查判断顺序

- **点击图标后立刻回到桌面**：优先看 AndroidRuntime / FATAL EXCEPTION；若没有异常堆栈，考虑系统强杀、ANR 或原生库崩溃。
- **应用界面出现但网页空白**：检查主文档 HTTP/网络错误、WebView 版本、站点部署地址和网页控制台错误。
- **只有某个功能失败**：优先导出「设置 → 运行诊断」报告，并记录复现步骤、设备型号、Android 版本和 APK 版本。
- **网页部署后才出问题**：APK 的 WebView 壳可能没变，但线上网页已变；记录发生时间和站点地址。
- **改动 Kotlin、Manifest、原生桥或权限声明后出问题**：必须重新构建并安装 APK；仅部署网页不能更新 APK 内的原生代码。

## 反馈时请提供

- APK 版本 / versionCode、Android 版本、设备型号、WebView 版本
- 问题类型：整个应用退出 / 原生恢复页 / 白屏 / 单个功能失败
- 复现步骤、出现时间、最近一次变更
- 应用内诊断摘要，或脱敏后的系统日志片段

不要提供密码、API Key、Cookie、Authorization 头、完整聊天记录或角色记忆。
