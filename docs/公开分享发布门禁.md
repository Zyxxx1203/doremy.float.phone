### WebView 原生桥 frame 隔离

Android 1.0.29 已将原始 Shell / Widget API 改为 nonce-gated RPC dispatcher：WebView 所有 frame 只能看到受限的 Secure 接口；真正的 AndroidShell / PhoneWidget wrapper 仅在配置站点的顶层 origin 注入，并且每次调用都校验随机 nonce。支持 document-start script 的 WebView 使用 origin-scoped 注入；不支持时退回主文档 onPageStarted 注入。CI 已加入静态契约检查，确保不再直接暴露原始桥对象。

**仍待真机安全验收**：需要在真实 Android WebView 中嵌入跨域测试 iframe，确认 iframe 无法调用敏感原生方法，同时验证顶层 AndroidShell 与 PhoneWidget 功能完整。静态源码检查不能替代这项端到端测试；完成前仍保持 Release Candidate。

第三方视频平台可能有登录、风控、地区、DRM、签名和版权限制。不能把“支持链接输入”描述成“保证所有视频都能播放”。

## 云端与密钥

1. `NEXT_PUBLIC_*` 会进入客户端构建产物，只能放公开配置；service role、后台密钥、签名密钥和第三方私钥不得放入客户端变量或仓库。
2. 用户个人 Supabase 与站点运营 Supabase 是不同部署边界；SQL、Edge Function、Realtime、Cron 和 RLS 都需要独立核对。
3. 更新 `supabase/functions/**` 不会自动更新用户项目中的 Edge Function，必须按文档重新部署。
4. 默认本机存储、用户主动启用的云同步、第三方 LLM/生图/语音/视频服务要分别说明数据会发送到哪里。
5. 发布前检查仓库历史、工作流日志、Artifacts、示例配置和文档，确认没有真实 token、service-role key、keystore 或个人数据。

## Android APK 分发规则

- `float-shell-debug` 是用于测试的 debug 签名包；若 CI 每次生成不同 debug key，覆盖安装可能失败，用户需配置固定签名或卸载旧包（卸载前必须备份）。
- `float-shell-release-signed` 仅在完整配置 keystore 与密码后生成；没有签名密钥时不发布未签名 release 包。
- 正式更新必须保持同一 applicationId、签名证书和递增 versionCode。
- APK 能安装不代表全部原生权限和后台能力都能工作；每种能力都要按实际授权和系统限制验收。

## 每次发布前的操作

1. 确认 main 最新提交，检查工作区和生成产物没有遗漏。
2. 运行 `npm ci`、`npx tsc --noEmit`、`npm run test:life`、`npm run build` 和所有模块专用测试。
3. 运行 `npm audit`，逐项处理 critical/high 漏洞并记录例外原因。
4. 检查 Supabase SQL / RLS / Edge Functions 与客户端 schema 是否一致。
5. 构建 debug APK；配置正式密钥后再构建 signed release APK。
6. 按设备矩阵逐项实测，并记录型号、系统版本、WebView 版本、权限状态、操作步骤、预期结果、实际结果和日志。
7. 备份数据后测试升级覆盖安装、恢复备份和回滚路径。
8. 更新 README、变更记录、已知限制和版本号，再创建 GitHub Release。

## 当前明确不能宣称的事项

- 不能宣称已在所有 Android 品牌、系统版本和 WebView 上完整兼容。
- 不能宣称 APP 被强制停止后所有后台功能仍能持续运行。
- 不能宣称 Supabase Edge Function 已自动部署到每位用户的项目。
- 不能宣称所有第三方视频链接均可解析或播放。
- 不能把自动化测试通过等同于 Android 真机 E2E 通过。
- 不能在依赖安全、权限隐私和授权清单未核对前称为正式稳定发行版。

## 发布完成定义

只有当本文件所有发布门禁均有可追溯证据、critical/high 漏洞已处置、默认安装流程可复现、关键功能在目标设备矩阵中通过、部署与隐私说明准确时，才将项目状态改为“可正式公开分享”。
