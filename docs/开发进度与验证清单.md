## 二、必须单独验证的消息链路

这些链路不能仅凭页面显示或代码存在判定完成：

1. **通知栏回复回写**：收到通知 → 直接回复 → 服务端/本地消息成功写入 → 生活现场消息记录可见 → 角色后续上下文读取到该条消息。
2. **后台主动消息持续运行**：配置主动触发条件 → 应用在前台/后台/锁屏/清理最近任务/重启后的行为分别记录 → 检查触发、去重、失败重试与通知展示。不要把「应用进程被强制停止」和普通后台状态混为一谈。
3. **在线聊天通知与生活系统通知**：分别触发两种通知，检查是否重复、互相覆盖、错误跳转或重复回写。
4. **云端与本地降级**：断网或云服务失败时检查内置回复是否生效；恢复网络后检查消息是否重复发送或顺序错乱。
5. **诊断链路**：每个失败场景都应能记录触发源、时间、目标角色/会话、处理阶段、结果和错误原因；诊断报告不得自动上传私密聊天内容。
